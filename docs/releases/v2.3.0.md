# GBF Accelerator v2.3.0 发布说明 (Release Notes)

> **发布日期**：2026-09-29  
> **版本定位**：SLRU 缓存完善、全局 RAM Boost 统一预算与 Prefetch 死链过滤  
> **发布包**：
> - Windows：`GBF_Accelerator_v2.3.0_GUI.zip`
> - macOS：`GBF_Accelerator_v2.3.0_macOS_universal2.zip`
> - Android (Root / LSPosed 模块)：`GBF_Accelerator_v2.3.0_Xposed_arm64.apk`

v2.3.0 在现有 Go 原生架构基础上，进一步完善 SLRU 分段缓存机制，引入 RAM Boost 激进内存缓存与统一内存预算管理，增加后台 Prefetch 对 404/410 失效素材的动态过滤抑制，优化 Web 控制台实时日志多词检索与平台按键自适应，并加固测试内存隔离与工具链路径锚定。

## 📥 下载与使用

### Windows 用户
1. 下载 `GBF_Accelerator_v2.3.0_GUI.zip`，解压即用；
2. **旧版本升级**：
   - **方式一（推荐，控制台一键更新）**：在控制台版本卡片直接点击【一键下载新版安装包】，SHA-256 校验通过后点击【立即更新并重启】平滑升级；
   - **方式二（手动替换）**：退出正在运行的旧版程序，直接使用压缩包内的 `GBF_Accelerator.exe` 覆盖替换原有文件即可；原有的 `cache` 缓存目录与 `config.json` 自动继承。

### macOS 用户
1. 下载 `GBF_Accelerator_v2.3.0_macOS_universal2.zip`（Universal 2 双架构，原生兼容 Intel 与 Apple Silicon Macs）；
2. 解压后将 `GBF_Accelerator.app` 拖入系统的【应用程序】（Applications）文件夹覆盖；
3. **解除安全拦截（首次运行必须）**：  
   打开终端执行以下命令清除系统隔离属性：
   ```bash
   xattr -cr /Applications/GBF_Accelerator.app
   ```
4. 启动后程序自动打开内嵌 Web 控制台。

### Android 用户
- **免 Root 用户**：
  1. 在 PC 端打开控制台，切换至【Android 浏览器修补】页面；
  2. 准备好官方原版 SkyLeap 安装包（或系统 WebView 浏览器 APK），拖入页面即可一键检测依赖并注入加速核心；
  3. 将生成的安装包传至手机安装（若手机连接电脑开启了 USB 调试，可直接点击控制台的【一键安装到手机】）；
  4. 安装后在手机上直接打开修补版浏览器即可使用，无需后台常驻。
- **已 Root / LSPosed 用户**：
  - 可直接下载下方附件中的 `GBF_Accelerator_v2.3.0_Xposed_arm64.apk` 安装并在 LSPosed 管理器中激活模块，勾选官方原版 SkyLeap 或 Via 浏览器即可直接打开使用，无需修改或重打包宿主 APK。

> **网络环境与 ACGPower 说明**：
> - 手机端内嵌核心默认以直连模式（`direct_mode=true`）运行，配合主流基于 TUN 网卡的网络工具（如 Clash、v2rayNG、Sing-box、网易UU加速器、奇游、岛风go 等）均可正常使用；
> - **暂不支持安卓版 ACGPower (acgp)**：由于安卓端 ACGPower 并非标准 IP 隧道，而是通过 `tun2socks` 重定向到本地代理且每次启动随机分配动态端口，无法做透明直连转发。若在手机上使用 ACGPower，建议直接使用其官网提供的定制版 SkyLeap 客户端。
>
> **多浏览器切换注意事项（Android 进程冻结机制）**：  
> Android 系统后台管理机制（cgroup v2 freezer）会在应用退入后台后冻结挂起其所有子进程（包括内嵌的 Go 加速核心），且应用私有沙盒相互隔离。若您在同一设备上安装了多个适配浏览器（如 SkyLeap 与 Via），**在切换浏览器前，请务必在多任务界面中将前一个浏览器彻底上滑关闭**，避免后台被冻结的核心占用 8124 端口导致新浏览器请求未响应。

## 🚀 主要更新

### ⚡ SLRU 缓存完善与全局 RAM Boost 统一预算

针对拥有充裕内存的桌面设备，进一步加固 SLRU 分段缓存准入并引入全新 RAM Boost 内存缓存机制：

* **按需自选开启**：RAM Boost 功能属于可选增强项，用户可根据设备硬件与需求选择开启；平时不开启时本地磁盘缓存已足够迅速，开启后主要进一步消除磁盘 I/O 抖动，将素材响应时间进一步稳定缩短约几毫秒 (几 ms)；
* **统一内存预算管辖**：重构 RAM 预算调度器，建立全生命周期统一内存配额管理，防止分段缓存与激进缓存并发争抢；
* **RAM Boost 全量预热与常驻**：支持将高频战斗、立绘等热点素材常驻在超低延迟 RAM 中，提升切页与重复战斗加载流畅度；
* **低内存安全停止守卫 (Low-Memory Stop Guard)**：引入系统可用内存水线探测；当宿主物理内存低于安全阈值时，自动中止预热或跳过激进缓存，坚决杜绝因激进预载引发系统 OOM；
* **并发生命周期与状态平滑切换**：全面加固 Boost 启动、执行与重载时的并发状态机，保障在途读写不被意外中断。

### 🛡️ Prefetch 404/410 失效素材过滤与防请求风暴

针对官方 Akamai CDN 上因历史更迭已失效的死链素材，优化后台预取引擎调度：

* **DeadFilter 动态失效表**：内置有界 LRU 失效素材过滤器，当 Prefetch 探测到上游返回 `404 Not Found` 或 `410 Gone` 时，自动记入过滤表并指数退避；
* **消除重复请求风暴**：阻止后续 bundle 再次解析出相同失效路径时对上游发起无效请求，大幅净化控制台日志并降低跨海请求开销；
* **业务透明穿透不污染**：DeadFilter 严格仅作用于后台 Prefetch 异步管线；前台用户的真实业务请求 100% 直连上游，绝不短路拦截。

### 📊 实时日志多词高亮与 macOS 原生键位自适应

进一步提升 Web 控制台排查定位与交互体验：

* **多关键词独立高亮匹配**：日志检索框支持以空格分割多个关键词（如 `quest json`），系统将分别独立高亮各关键词匹配项，直观凸显复合条件；
* **macOS 原生快捷键自适应**：日志搜索自适应 macOS 原生规范快捷键（`Cmd+G` 跳转下一项、`Cmd+Shift+G` 跳转上一项），并根据客户端操作系统动态显示按键图标（`⌘` 与 `F3`）；
* **快捷键冲突消除**：彻底修复浏览器原生 `Ctrl+F` / `Cmd+F` 与应用内日志搜索的事件捕获冲突。

### 🛠️ Android 浏览器修补工具相对路径锚定

* **工作目录漂移修复**：修复 Android Patcher 工具对相对输出路径（如 `./output`）的解析逻辑，严格将其锚定在应用程序根基准目录下，避免在不同启动路径或跨平台桌面快捷方式下导致输出目录漂移。

### 🛡️ 稳定性与透明性

本版本继续严格遵循安全治理不变量：

* 动态游戏 API 原样透明转发，业务 Header 与 Body 零修改；
* POST / PUT / DELETE 状态变更请求绝对零重试；
* 静态资源缓存保持 Akamai CDN 原始字节流，无任何反检测伪装；
* 后台 Prefetch 主动避让前台请求；
* Windows、macOS、Linux、Android 各平台严格保持架构隔离。

## 🧭 验证边界 (Verification Boundaries)

### 已验证 (Verified)
- **Windows 桌面端**：Windows 10 / 11 真实桌面环境、RAM Boost 激进内存缓存生命周期、独立控制台窗口居中与几何记忆、Edge FRE 欢迎弹窗屏蔽、系统代理托管与托盘生命周期。

- **缓存与预取管线**：SLRU 来源感知分段保护、Prefetch 404/410 失效素材动态过滤与指数退避。

### 未验证 (Unverified / Environment Dependent)
- **跨物理设备 Wi-Fi 复杂拓扑**：局域网共享模式下，跨物理设备通信受用户本地路由器 AP 隔离、多级子网及防火墙规则影响，需用户在本地网络实测。
- **Android 定制 ROM 多样性**：不同手机品牌定制系统（如 HyperOS、OriginOS、ColorOS、HarmonyOS 等）对 WebView 的深度定制与后台省电策略差异，需在具体真机上实际体验。
- **macOS 实机 Gatekeeper**：macOS 发布包首次运行仍需用户执行 `xattr -cr` 清除系统安全隔离属性。
