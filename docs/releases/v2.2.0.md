# GBF Accelerator v2.2.0 发布说明 (Release Notes)

> **发布日期**：2026-09-26  
> **版本定位**：移动端架构支持、分段缓存优化与高频请求调度  
> **发布包**：
> - Windows：`GBF_Accelerator_v2.2.0_GUI.zip`
> - macOS：`GBF_Accelerator_v2.2.0_macOS_universal2.zip`

v2.2.0 在现有 Go 原生架构基础上，进一步完善移动端使用方式，并继续优化本地缓存与高频请求路径。

---

## 📥 下载与使用

### Windows 用户
1. 下载 `GBF_Accelerator_v2.2.0_GUI.zip`，解压即用；
2. **旧版本升级**：
   - **方式一（推荐，控制台一键更新）**：可在控制台版本卡片直接点击【一键下载新版安装包】，SHA-256 校验通过后点击【立即更新并重启】平滑升级；
   - **方式二（手动替换）**：退出正在运行的旧版程序，直接使用压缩包内的 `GBF_Accelerator.exe` 覆盖替换原有文件即可；原有的 `cache` 缓存目录与 `config.json` 自动继承。

### macOS 用户
1. 下载 `GBF_Accelerator_v2.2.0_macOS_universal2.zip`（Universal 2 双架构，原生兼容 Intel 与 Apple Silicon Macs）；
2. 解压后将 `GBF_Accelerator.app` 拖入系统的【应用程序】（Applications）文件夹覆盖；
3. **解除安全拦截（首次运行必须）**：  
   打开终端执行以下命令清除系统隔离属性：
   ```bash
   xattr -cr /Applications/GBF_Accelerator.app
   ```
4. 启动后程序自动打开内嵌 Web 控制台。

### Android 用户
1. 在 PC 端打开控制台，切换至【Android 浏览器修补】页面；
2. 准备好官方原版 SkyLeap 安装包（或系统 WebView 浏览器 APK），拖入页面即可一键检测依赖并注入加速核心；
3. 将生成的安装包传至手机安装（若手机连接电脑开启了 USB 调试，可直接点击控制台的【一键安装到手机】）；
4. 安装后在手机上直接打开修补版浏览器即可使用，无需后台常驻；如需调整缓存参数，可在手机浏览器打开 `http://127.0.0.1:8125` 控制台调整（其他底层网络设置请勿修改）。

## 🚀 主要更新

### 📱 Android 客户端支持

新增基于 Go Core 的 Android 客户端架构，可在 Android 设备上直接运行本地加速核心。

* **用户自行嵌入（不分发修改版 APK）**：
  本工具不分发任何经过修改的第三方浏览器安装包。用户需在 PC 控制台【Android 浏览器修补】页面中，自行选择本地已有的官方原版安装包进行一键嵌入修补；
* **支持的浏览器类型**：
  - 优先推荐官方 **DeNA SkyLeap**；
  - 亦支持其他基于 Android 系统原生 **WebView** 的轻量浏览器（如 Via、X 浏览器等）；
  - *注：独立 Chromium / Gecko 内核浏览器（如 Chrome、Kiwi、Firefox 等）暂不支持；*
* **免 Root 与模块接入双支持**：支持控制台一键全自动打包注入（免 Root 安装即用），同时亦支持 LSPosed / Xposed 模块方式接入；
* **移动端默认资源与流量保护**：
  考虑到移动设备 RAM 容量限制及移动蜂窝网络状况，Android 端**默认关闭了“内存缓存 (RAM Cache)”与“后台预加载 (Prefetch)”**，以磁盘缓存与本地透明转发为主，优先保障低发热、低内存占用与流量安全；
* **按需开启与配置须知**：
  若手机配置较高且常在 Wi-Fi 下使用，可在手机补丁版浏览器中直接访问内置控制台：`http://127.0.0.1:8125` 手动开启内存缓存或预加载；  
  ⚠️ **请注意**：移动端环境特殊，控制台内的监听端口、网络模式等底层配置**请保持默认，切勿随意改动**，以免造成手机端服务异常或网络中断；
* **本地独立与生命周期管理**：
  静态素材使用 RAM + 磁盘双层缓存，动态 API 保持透明转发；运行时配置与缓存均使用应用私有目录，卸载后自动清理。Android 端与桌面端继续保持平台隔离。

### ⚡ 缓存与高频请求性能优化

继续针对 v2.1.1 之后的缓存热路径进行优化：

* RAM Cache 引入分段 LRU（SLRU）缓存策略；
* 后台 Prefetch 使用独立的缓存准入策略，减少冷数据对热点素材的挤占；
* Prefetch 与前台请求共享 SingleFlight，减少同一素材的重复上游请求；
* 优化磁盘缓存冷命中路径，减少不必要的文件状态检查；
* 优化高并发缓存访问与锁竞争；
* 增加更多并发、Prefetch、缓存边界及性能回归测试。

这些优化主要针对已经积累缓存后的重复加载、频繁切图以及连续战斗场景，进一步降低本地处理开销。

### 🖥️ Windows 控制台体验优化

* 优化独立控制台窗口的位置与尺寸恢复；
* 启动时根据当前显示器工作区调整窗口位置，避免跨屏或被任务栏遮挡；
* 减少 Edge App 模式首次运行时的额外提示干扰；
* 保持原有 Windows 托盘、系统代理及证书流程不变。

### 🛡️ 稳定性与透明性

本版本继续保持既有核心行为：

* 动态游戏 API 原样透明转发；
* POST / PUT / DELETE 等状态变更请求不进行重试；
* 静态缓存保持原始字节，不修改游戏素材；
* 后台 Prefetch 主动避让前台请求；
* 日志与遥测采用有界、非阻塞方式，不阻塞代理数据面；
* Windows、macOS、Linux、Android 继续保持平台隔离。

## 🧭 验证边界 (Verification Boundaries)

### 已验证 (Verified)
- **Windows 桌面端**：Windows 10 / 11 真实桌面环境、独立控制台窗口居中与几何记忆、Edge FRE 欢迎弹窗屏蔽、系统代理托管与托盘生命周期。
- **Web 控制台**：单二进制内嵌 SPA、Android 浏览器修补面板交互、依赖检测与 ADB 设备自动发现。
- **缓存与调度链路**：SLRU 来源感知分段保护、前后台在途任务复用、高并发读写锁竞争基准测试。
- **macOS 与 Linux 交叉编译**：各平台目标架构可执行文件与交叉编译二进制构建无报错。

### 未验证 (Unverified / Environment Dependent)
- **跨物理设备 Wi-Fi 复杂拓扑**：局域网共享模式下，跨物理设备通信受用户本地路由器 AP 隔离、多级子网及防火墙规则影响，需用户在本地网络实测。
- **Android 定制 ROM 多样性**：不同手机品牌定制系统（如 HyperOS、OriginOS、ColorOS、HarmonyOS 等）对 WebView 的深度定制与后台省电策略差异，需在具体真机上实际体验。
- **macOS 实机 Gatekeeper**：macOS 发布包首次运行仍需用户执行 `xattr -cr` 清除系统安全隔离属性。
