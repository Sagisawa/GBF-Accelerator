# GBF Accelerator v2.0.0 发布说明 (Release Notes)

> **发布日期**：2026-09-20  
> **版本定位**：Go 原生引擎重写、双平面拓扑隔离、内嵌 React SPA 控制台与跨平台加固  
> **发布包**：
> - Windows：`GBF_Accelerator_v2.0.0_GUI.zip`
> - macOS：`GBF_Accelerator_v2.0.0_macOS_universal2.zip`

---

## 📥 下载与使用

### Windows 用户
1. 下载 `GBF_Accelerator_v2.0.0_GUI.zip`，解压即用；
2. 旧版本升级直接替换 `GBF_Accelerator.exe` 即可，原有 `cache` 目录与 `config.json` 自动继承，无需重新配置。

### macOS 用户
1. 下载 `GBF_Accelerator_v2.0.0_macOS_universal2.zip`（Universal 2 双架构，原生支持 Intel 与 Apple Silicon Macs）；
2. 解压后将 `GBF_Accelerator.app` 拖入系统的【应用程序】（Applications）文件夹；
3. **解除安全拦截（首次运行必须）**：  
   打开终端执行以下命令清除系统隔离属性：
   ```bash
   xattr -cr /Applications/GBF_Accelerator.app
   ```
4. 启动后程序自动打开内嵌 Web 控制台（支持 Chromium App Mode 独立窗口），首次启动将自动引导完成钥匙串根证书信任与系统 PAC 代理配置。

## 🌟 主要更新内容

### 1. Go 原生引擎全面重构
- **零 Python 运行时依赖**：核心代理引擎完成 Go 原生重构，交付为单静态二进制文件，内存占用显著降低，并发调度能力与运行稳定性进一步增强。
- **数据面与控制面双端口隔离**：采用代理数据平面（默认 `:8124`）与管理控制平面（默认 `:8125`）双端口独立拓扑；控制平面内置 DNS Rebinding 与 CORS 来源白名单校验。
- **局域网共享与热重载隔离**：数据平面（`:8124`）支持随 `allow_lan` 配置在 `127.0.0.1` 与 `0.0.0.0` 之间无缝热重载（采用 Close-Listen-Rollback 事务机制）；局域网设备所需的根证书、PAC 脚本与落地页由 `:8124` 直接提供；管理控制平面（`:8125`）坚决保持 `127.0.0.1` 本地回环监听，杜绝局域网越权调用管理接口。
- **现代化内嵌 Web 控制台**：基于 React 18 + Vite 开发的管理界面编译后经 Go `embed` 内置于单二进制产物中，零外部依赖，支持深色/浅色模式、实时性能指标图表与日志流。

### 2. 核心网络与代理管道加固
- **API / Asset 物理连接池隔离**：动态游戏 API 采用专用 HTTP/1.1 Keep-Alive 连接池，静态素材走 Akamai CDN 专用 HTTP/2 多路复用连接池，杜绝协议降级与握手阻塞。
- **双重约束安全重试**：所有涉及状态变更的写请求（POST/PUT/DELETE）强制零重试（`maxAttempts = 1`）；只读 GET 请求仅限白名单安全路径重试，杜绝技能双发与状态不一致。
- **有界非阻塞遥测机制**：日志与状态推送采用有界非阻塞通道，队列满载时安全丢弃日志，确保管理控制台活动绝不阻塞代理核心数据面。

### 3. 跨平台适配与发布工程严格化
- **macOS 原生 .app 打包与分流指引**：macOS 发布包提供标准 `.app` Bundle 目录结构（包含 Info.plist、高分辨率 icns 图标与分发说明）；控制台路由引导内置 SmartProxy / ZeroOmega 4 步分流指引，无缝兼容 Clash TUN 虚拟网卡模式。
- **Windows 原生集成与图标嵌入**：Windows 原生可执行文件内置完整 7 规格高清应用图标与 PE 版本元数据（FileVersion: 2.0.0.0）；提供受控的 Windows 防火墙一键放行适配操作（限定为 Private / LocalSubnet / TCP），不越权开放公网。
- **系统调用平台隔离**：抽离 Windows、macOS 与 Linux 原生目录选择至平台适配层，清除公共包中 Windows 专有属性依赖，实现全平台交叉编译 100% 通过。
- **移动端全流程图文指引**：局域网落地页（`:8124/`）与 Web 控制台弹窗同步集成详尽的根证书安装步骤、iOS 证书信任设置开关与 Wi-Fi 代理分流图文说明。
- **构建脚本发布合同加固**：构建脚本严格约束 macOS Universal 2 必须在具备 `lipo` 工具的环境下生成，缺失或合并失败时直接报错中断，坚决不产出伪装的单架构 Universal2 包。

## 🔒 事务与安全边界 (Transaction & Security Boundaries)

明确界定双平面监听策略与暴露边界，守住核心安全红线：

- **8124 = 数据平面 (Data Plane)**
  - 默认监听：`127.0.0.1`
  - 开启局域网共享（`AllowLAN = true`）时：动态重载至 `0.0.0.0`
  - 承载职责与公开资源：
    - HTTP / HTTPS 游戏透明代理与流量分流
    - `/ca.crt`（本地自签根证书下载）
    - `/proxy.pac`（PAC 自动代理脚本）
    - 局域网移动端接入引导向导页
- **8125 = 控制平面 (Control Plane)**
  - 监听策略：**永远严格绑定 `127.0.0.1`，绝不暴露至局域网（Never exposed to LAN）**
  - 承载职责：
    - 管理控制台 React SPA 前端资源
    - 系统管理与配置变更 REST API（`/api/config`、`/api/status`、`/api/app/quit` 等）
    - 实时性能与连接 SSE 遥测流
    - 内置 DNS Rebinding 防护与 Host / Origin 白名单严格校验

## 🔄 配置热重载行为 (Configuration Hot-Reload Pipeline)

系统配置热重载（`POST /api/config/apply`）遵循严格的四阶段强事务流水线：

```text
[Candidate] (候选配置生成与字段校验)
    ↓
[Commit] (内存配置原子提交与磁盘持久化)
    ↓
[Listener Rebind] (网络监听强事务重载: 8124 / 8125 端口与 Host 切换)
    ↓
[Post-Commit Runtime Sync] (非监听运行时副作用生效: 缓存目录/RAM 上限/PAC 代理/自启)
```

### 异常故障原子回滚保障
- **Rebind 阶段失败**（如目标端口被占用）：
  - 自动回滚至旧 Listener；
  - 配置状态保持未修改（Config unchanged）；
  - 向调用端返回失败错误。
- **Save/Commit 阶段失败**（如磁盘写保护或 I/O 错误）：
  - 自动回滚已重绑的 Listeners 至原端口与原监听地址；
  - 内存配置立即还原为旧配置（Memory config restored）；
  - 磁盘文件保持原样（Config on disk unchanged）；
  - **彻底阻断 Post-Commit 运行时副作用**（sysproxy 不执行、startup 不执行、cache runtime 不切换）。

> 💡 **语义规范**：`cfgMgr.Update()` 仅用于安全的内存就地原子更新；`cfgMgr.Commit()` 承载包含磁盘落盘校验、两端监听联动与强事务回滚保障的完整语义。
