# GBF Accelerator v2.4.0 发布说明 (Release Notes)

> **发布日期**：2026-10-01  
> **版本定位**：传输架构代际跃迁，从整块下载升级为实时响应，引入 Stream-Through 流式边下边传与内存元数据索引，大幅降低大素材 TTFB、I/O 与内存开销  
> **发布包**：
> - Windows：`GBF_Accelerator_v2.4.0_GUI.zip`
> - macOS：`GBF_Accelerator_v2.4.0_macOS_universal2.zip`
> - Android (Root / LSPosed 模块)：`GBF_Accelerator_v2.4.0_Xposed_arm64.apk`

v2.4.0 是一次针对静态资源缓存与传输链路的深度优化，同时完善了 Android 移动端修补工作流。

过去版本采用整包下载完成后再交付的机制，对于未命中缓存的大体积素材（立绘大图、BGM 音频、战斗动画等），浏览器必须等待代理将上游文件完整接收并检验落盘后才能收到响应。**本版本引入 Stream-Through（流式边下边传）机制**，上游数据到达后持续向浏览器流式推送，使冷请求的首字节响应时间（TTFB）不再受文件整体体积制约；同时配合分级缓冲、大文件直读与内存元数据索引，大幅减少高并发下的磁盘 I/O 抖动与瞬时内存分配。

Android 端则新增已修补包检测与自动还原管线，支持普通 APK 与 Split APK，让已被旧版核心修补过的安装包可以直接拖入重新修补并无缝升级至最新核心。

## 📥 下载与使用

### Windows 用户
1. 下载 `GBF_Accelerator_v2.4.0_GUI.zip`，解压即用；
2. **旧版本升级**：
   - **方式一（推荐，控制台一键更新）**：在控制台版本卡片直接点击【一键下载新版安装包】，SHA-256 校验通过后点击【立即更新并重启】平滑升级；
   - **方式二（手动替换）**：退出正在运行的旧版程序，直接使用压缩包内的 `GBF_Accelerator.exe` 覆盖替换原有文件即可；原有的 `cache` 缓存目录与 `config.json` 自动继承。

### macOS 用户
1. 下载 `GBF_Accelerator_v2.4.0_macOS_universal2.zip`（Universal 2 双架构，原生兼容 Intel 与 Apple Silicon Macs）；
2. 解压后将 `GBF_Accelerator.app` 拖入系统的【应用程序】（Applications）文件夹覆盖；
3. **解除安全拦截（首次运行必须）**：  
   打开终端执行以下命令清除系统隔离属性：
   ```bash
   xattr -cr /Applications/GBF_Accelerator.app
   ```
4. 启动后程序自动打开内嵌 Web 控制台。

### Android 用户
- **免 Root 用户**：
  1. 在 PC 端打开控制台，切换至【Android 浏览器修补】页面；
  2. 支持直接拖入官方原版或已被旧版核心修补过的安装包，系统会自动识别并提示【重新修补 / 升级核心】；
  3. 点击制作后自动还原未注入核心的原版并注入最新版加速引擎；
  4. 生成安装包后传至手机安装（或通过 USB 调试【一键安装到手机】）即可使用。
- **已 Root / LSPosed 用户**：
  - 可直接下载下方附件中的 `GBF_Accelerator_v2.4.0_Xposed_arm64.apk` 安装并在 LSPosed 管理器中激活模块，勾选官方原版 SkyLeap 或 Via 浏览器即可直接打开使用，无需修改或重打包宿主 APK。

> **网络环境与 ACGPower 说明**：
> - 手机端内嵌核心默认以直连模式（`direct_mode=true`）运行，配合主流基于 TUN 网卡的网络工具（如 Clash、v2rayNG、Sing-box、网易UU加速器、奇游、岛风go 等）均可正常使用；
> - **暂不支持安卓版 ACGPower (acgp)**：由于安卓端 ACGPower 并非标准 IP 隧道，而是通过 `tun2socks` 重定向到本地代理且每次启动随机分配动态端口，无法做透明直连转发。若在手机上使用 ACGPower，建议直接使用其官网提供的定制版 SkyLeap 客户端。
>
> **多浏览器切换注意事项（Android 进程冻结机制）**：  
> Android 系统后台管理机制（cgroup v2 freezer）会在应用退入后台后冻结挂起其所有子进程（包括内嵌的 Go 加速核心），且应用私有沙盒相互隔离。若您在同一设备上安装了多个适配浏览器（如 SkyLeap 与 Via），**在切换浏览器前，请务必在多任务界面中将前一个浏览器彻底上滑关闭**，避免后台被冻结的核心占用 8124 端口导致新浏览器请求未响应。

## 🚀 核心更新

### ⚡ Stream-Through 流式缓存传输

重新优化静态资源从上游到浏览器的完整传输链路：

* **Cache Miss Stream-Through（冷请求流式交付）**：  
  缓存未命中时，静态资源无需等待上游完整下载即可开始向浏览器交付；数据随到随传，前台响应与后台落盘缓存进一步解耦，明显改善大体积素材的首字节等待时间（TTFB）；
* **分级缓冲策略（Tiered Buffering）**：  
  小型资源继续使用高效批量处理；中等体积资源采用内存流式管道传输；超大资源按需使用安全临时文件承载，避免单个大文件请求产生过大的瞬时内存占用；
* **Verified Large-Asset Direct Streaming（已验大文件直接流式读取）**：  
  已完成完整性验证的磁盘大体积缓存可直接以流式读取交付，避免将整个文件重复加载至 RAM 内存；
* **HEAD / Conditional Request Fast Path（极速元数据路径）**：  
  对 HEAD 与协商缓存条件请求（304）优先使用元数据短路响应，无需读取完整正文即可完成判定，减少无意义的磁盘 I/O。

---

### 🧠 Cache / Disk Cache 性能与并发优化

* **Disk Metadata Index（内存元数据索引）**：  
  引入内存中的磁盘元数据索引，消除磁盘缓存命中时的额外元数据读取与文件探测，进一步降低冷命中的本地处理开销；
* **SLRU 准入治理与 RAM 预算解耦**：  
  大体积静态文件默认不再进入基础 SLRU 内存缓存，避免频繁挤占高频小资源；而 RAM Boost ResidentPool 仍可在统一内存预算范围内按需常驻热点素材；
* **锁竞争优化与 GC 压力降低**：  
  优化高并发场景下的读写锁竞争，减少缓存保存过程中的不必要计算与临时对象分配，降低运行时 GC 停顿；
* **缓存完整性联合校验与回退**：  
  读取磁盘缓存时严格校验文件大小与修改时间，发生缓存文件异常时安全回退至正常 Cache Miss 流程。

### 📱 Android 已修补 APK 自动还原与重新修补

彻底解决移动端面对已被 LSPatch 修补过的安装包无法直接升级核心或再次修补的痛点：

* **已修补包自动特征识别**：  
  Patcher 会自动嗅探 APK 内部的 LSPatch 特征，精准识别是否已包含核心、修补类型、内嵌 Origin APK 以及原始应用 Package Name 与真实版本信息，并在控制台清晰展示；
* **自动还原并重新修补**：  
  检测到已修补安装包后，无需用户手动解包、导出、重命名后再次导入，程序自动流式提取原始 APK 并完成完整性校验，直接无缝使用当前核心重新修补并升级；
* **Split APK 分包原生结构恢复**：  
  支持普通 APK 与 Split APK 分包，通过解析原始 AXML Manifest 精确恢复 base 与 split 身份；
* **单层解包与安全兜底**：  
  严格限制仅允许自动解包一层，杜绝嵌套修补风险；全面内置 Zip Slip 路径穿越防御与 CRC-32 损坏完整性校验。
