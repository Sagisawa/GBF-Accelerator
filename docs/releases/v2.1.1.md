# GBF Accelerator v2.1.1 发布说明 (Release Notes)

> **发布日期**：2026-09-23  
> **版本定位**：基于 Go 原生架构的持续性能优化、缓存加速与稳定性维护  
> **发布包**：
> - Windows：`GBF_Accelerator_v2.1.1_GUI.zip`
> - macOS：`GBF_Accelerator_v2.1.1_macOS_universal2.zip`

v2.0 完成 Go 原生核心重构后，后续版本持续围绕缓存、并发、Prefetch 及请求处理路径进行优化。

本次 v2.1.1 集中收敛 2.1.0 之后的一系列底层优化，进一步降低本地静态资源处理开销。

---

## 📥 下载与使用

### Windows 用户
1. 下载 `GBF_Accelerator_v2.1.1_GUI.zip`，解压即用；
2. **旧版本升级**：
   - **方式一（推荐，控制台一键更新）**：若当前运行 v2.1.0，可在控制台版本卡片直接点击【一键下载新版安装包】，SHA-256 校验通过后点击【立即更新并重启】平滑升级；
   - **方式二（手动替换）**：退出正在运行的旧版程序，直接使用压缩包内的 `GBF_Accelerator.exe` 覆盖替换原有文件即可；原有的 `cache` 缓存目录与 `config.json` 自动继承。

### macOS 用户
1. 下载 `GBF_Accelerator_v2.1.1_macOS_universal2.zip`（Universal 2 双架构，原生兼容 Intel 与 Apple Silicon Macs）；
2. 解压后将 `GBF_Accelerator.app` 拖入系统的【应用程序】（Applications）文件夹覆盖旧版；
3. **解除安全拦截（首次运行必须）**：  
   打开终端执行以下命令清除系统隔离属性：
   ```bash
   xattr -cr /Applications/GBF_Accelerator.app
   ```
4. 启动后程序自动打开内嵌 Web 控制台。

## 🚀 主要更新内容

### 1. 游戏体验优化

本次更新主要体现在**已经缓存到本机的资源重复加载场景**：

* 页面切换、返回已访问页面时更加利落；
* 已缓存的图片、脚本及其他静态资源响应更快；
* 连续战斗、频繁切换游戏界面时，重复资源请求的本地处理开销更低；
* 对已经积累较完整缓存的用户，整体效果更加明显。

> *注：本次更新主要优化本地缓存与请求处理效率，不直接改变 GBF 服务器的网络 RTT。*

### 2. Go 原生架构持续性能优化

基于 v2.0 的 Go 原生核心架构，继续针对高频请求路径进行优化：

* **无锁配置快照读取**：优化配置状态读取，引入原子不可变快照，减少高频访问中的同步开销（Lock-free reads）；
* **静态资源路径防抖**：优化静态资源路径规范化，减少重复字符串处理；
* **低开销请求响应路径**：优化缓存请求与响应路径，降低本地处理开销；
* **架构纯粹性保持**：保持纯 Go、跨平台及现有双平面架构不变。

### 3. RAM / Disk Cache 性能优化

* 优化 RAM Cache 高并发访问路径及 SingleFlight 分片，降低并发锁竞争；
* 优化 Disk Cache 元数据与缓存查找；
* 优化负缓存结构及查找效率，并修复缓存保存后的负缓存清理问题；
* 优化已规范化 Header 的快速处理路径；
* 优化缓存资源响应，减少中间对象构造；
* 进一步优化 RAM Cache Hit 热路径，消除重复 Host 解析及临时内存分配。

本次最新优化后，内部高并发 Benchmark 中：

* **RAM Cache 热路径**：`5 allocs/op → 0 allocs/op`（零额外内存分配）
* **16 Worker 基准下**：`159.2 ns/op → 120.0 ns/op`

> *注：以上数据为本地微基准测试，用于衡量 GBF Accelerator 自身的请求处理开销，不代表实际游戏网络延迟。*

### 4. Prefetch 与请求处理优化

* 优化 Prefetch 中重复路径规范化，降低后台预取任务的额外处理开销；
* 保持前台请求优先与后台平滑预取机制；
* 减少静态资源请求中的重复解析。

### 5. 稳定性与业务透明性

* 保持动态 API 原样透明转发；
* 不修改动态请求参数、Cookie 及核心业务接口处理逻辑；
* 不新增额外上游请求；
* 保持现有缓存目录及配置兼容性；
* 保持备用上游、Prefetch 及现有代理工作方式；
* 保持 Windows、Linux、macOS 多平台支持。
