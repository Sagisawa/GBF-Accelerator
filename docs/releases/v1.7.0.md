# GBF Accelerator v1.7.0

本版本调整了后端的网络请求管理，将动态 API 与静态资源分别使用独立的 HTTP Client 处理，在 API 通道中启用了 TCP 连接复用与只读请求重试，并为客户端界面添加了实时日志查看功能。

---

## 更新内容

### 1. API 与静态资源使用独立 Client
- **原因**：此前动态 API 请求与静态资源（及后台 Prefetch）共用同一个连接池，在并发下载较多静态文件时，可能会竞争连接资源，导致部分 API 出现排队延迟。
- **调整**：拆分为两个独立的 `httpx.AsyncClient` 实例：
  - `api_client`：专门处理动态游戏 API（如 `/rest/`、`/socket/`、`/content/` 等），使用独立连接池，避免被静态资源请求排队影响。
  - `asset_client`：专门处理静态资源下载与后台 Prefetch 队列。

### 2. 连接池配置与 TCP 连接复用
- **动态 API 通道**：
  - 固定使用 HTTP/1.1，匹配游戏 API 服务器协议。
  - 连接池参数设为 `max_connections=16, max_keepalive=4, keepalive_expiry=20s`。
  - 连续发送请求时会尽量复用已有 TCP 连接，省去重新建立 TCP+TLS 握手的时间开销。
- **静态资源通道**：
  - 保留 HTTP/2 支持，连接池参数为 `max_connections=100, max_keepalive=40, keepalive_expiry=60s`。

### 3. 只读 GET 请求失效重试
- **原因**：Keep-Alive 空闲长连接有时会被服务端关闭。若客户端在断开瞬间尝试复用该连接，会触发 `RemoteProtocolError` 或连接重置。
- **规则**：
  - POST 请求及其他可能改变状态的请求一律不重试。
  - 仅针对预设白名单内的只读 GET 接口（如 `/socket/query`、`/content/index/`、`/rest/multiraid/start.json` 等），在初次断开时尝试重新建连并重发一次，减少偶发的断连报错。

### 4. GUI 实时日志查看窗口
- 主界面底部增加「实时日志」按钮，点击可打开独立日志窗口。
- 日志中会标注连接是否为复用（`reused`）或新建（`new`），方便观察连接池状态。
- 支持关键词搜索和按类型筛选（API、缓存、预取、错误等）。
- 日志采用异步队列传递，避免界面渲染影响代理处理速度。

### 5. 其他修复与调整
- 修复 `prefetch_worker` 调用 `request_asset` 时缺少默认参数导致的报错。
- 修复局域网 PAC 接口在部分情况下的参数传递问题。
- 测试用例增加至 47 项（包含连接池复用与 Prefetch 流程测试），全部通过。
